# Publishing a source

A source is an origin that hands out two kinds of JSON.

1. A **manifest** at a URL you expect clients to store and share.
2. A **feature collection** at each `resources[].href`.

The manifest’s own `href` is that canonical manifest URL. It should stay stable
when you move files behind it. Resource URLs and feature `href`s follow the same
rule: the identifier is the URL, not a name generated by the client.

## What the manifest carries

Required fields are `href`, `name`, `description`, and `resources`. `icon` is
optional. Each resource has an `href` and a `type`. The current type is
`feature-collection`.

A resource can list `layers`. A layer has a `name`, and may include a
description, an icon, `options`, and `parameters`.

- `options` are drawing hints, such as `icons` or `labels`. The client decides
  how to honor them.
- A `parameter` is either a `key` and `value`, or a `filter` string. The source
  defines what those mean for its collections. A client passes them along when
  it requests the resource, or interprets them when it filters features it
  already has.

## Authentication

If `auth` is absent, the source is public. If it is present, each entry names a
method. Version 1 defines `basic`, HTTP Basic authentication. Declare every
method you accept. Clients should not guess a method that the manifest does not
list.

## Feature collections

A collection is a GeoJSON `FeatureCollection` plus an `href` for the collection.
Each feature is a GeoJSON feature plus its own `href`, and may include a
`metadata` object for properties that are not part of the GeoJSON `properties`
object.

Serve the collection at the resource `href` from the manifest. Keep those two
URLs the same document: the manifest points at the collection, and the
collection’s `href` identifies itself.
